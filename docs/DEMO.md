# React Demo เดิม — SkillTrust Academy

เอกสารนี้ใช้กับ `src/` โหมดสาธิตเดิมเท่านั้น เว็บจริงบน Sepolia อยู่ใน `web/` ตาม README หลัก

Frontend ภาษาไทยสำหรับระบบออกและตรวจสอบใบรับรองดิจิทัล ใช้ React, TypeScript strict, Vite, viem และ SHA-256 ในเบราว์เซอร์

**รุ่นนี้เป็นโหมดสาธิตทั้งหมด ยังไม่เชื่อม Smart Contract และไม่มีการส่งธุรกรรมบน Blockchain** การตั้งค่า Address ใน `.env` เพียงอย่างเดียวจะไม่เปลี่ยนเป็นโหมดจริง

## เริ่มใช้งาน

ใช้ Node.js 22.12 ขึ้นไป และ npm เปิด Terminal ในโฟลเดอร์ `skilltrust-certificate` แล้วรัน:

```powershell
npm ci
npm run dev:demo
```

เปิด http://localhost:5177 ตาม URL ที่ Vite แสดง หากพอร์ตถูกใช้งาน Vite จะเลือกพอร์ตถัดไป สามารถตรวจด้วย `npm run dev -- --strictPort` เพื่อให้หยุดแทนการเปลี่ยนพอร์ต

```powershell
npm test
npm run build:demo
npm run preview
```

`npm run build` ตรวจ TypeScript ทั้ง source และ tests แล้วสร้างเว็บใน `dist/` สำหรับ static hosting ใช้ base path แบบ relative และ URL `?certificate=...` จึงไม่ต้องตั้งค่า server-side route rewrites

## ทดลองครบทุกขั้นตอน

1. เปิดหน้า **ตรวจสอบใบรับรอง** ค้นหา `ST-2026-001` สำหรับใบที่มีผลใช้งาน หรือ `ST-2026-003` สำหรับใบที่ถูกเพิกถอน ค้นหา `MISSING` เพื่อทดลองกรณีไม่พบ
2. ดาวน์โหลด PDF ตัวอย่างจากส่วน **เอกสารตรงกันไหม?** แล้วเลือกไฟล์เดิมเพื่อตรวจ Hash ไฟล์ตัวอย่างเดียวกันใช้กับใบรับรองเริ่มต้นทั้งสามใบ หากแก้ไข bytes ของไฟล์แล้วตรวจใหม่ Hash จะไม่ตรงกัน
3. เลือกบัญชีสาธิต **ผู้ดูแลระบบ** จากแถบด้านบน เปิด **หลักสูตรการอบรม** แล้วสร้างหลักสูตร เช่น `WEB-301`
4. เลือก **ผู้ออกใบรับรอง** หรือใช้ผู้ดูแลระบบ เปิด **ออกใบรับรอง** กรอกรหัสใหม่ เลือกหลักสูตร วันที่ไม่เกินวันนี้ Wallet ผู้รับ และ PDF ขนาดไม่เกิน 20 MB ระบบคำนวณ SHA-256 ในเครื่องก่อนบันทึก
5. ใช้ Wallet ผู้รับสาธิต `0x3333333333333333333333333333333333333333` จากนั้นเลือกบัญชี **ผู้รับใบรับรอง** และเปิด **ใบรับรองของฉัน** เพื่อดูรายการใหม่
6. เปลี่ยนเป็น **ผู้ดูแลระบบ** เปิดรายละเอียดใบรับรองแล้วกด **เพิกถอนใบรับรองนี้** และยืนยัน ประวัติการออกและ Hash ยังอยู่ รหัสใบรับรองที่เพิกถอนแล้วนำมาใช้ซ้ำไม่ได้
7. กดปุ่มรีเซ็ตข้างตัวเลือกบัญชีและยืนยัน เพื่อคืนค่าข้อมูลเริ่มต้น

| บัญชีสาธิต     | Wallet                                       | สิทธิ์                       |
| -------------- | -------------------------------------------- | ---------------------------- |
| ผู้ดูแลระบบ    | `0x1111111111111111111111111111111111111111` | สร้างหลักสูตร ออก และเพิกถอน |
| ผู้ออกใบรับรอง | `0x2222222222222222222222222222222222222222` | ออกใบรับรอง                  |
| ผู้รับใบรับรอง | `0x3333333333333333333333333333333333333333` | ดูใบรับรองของตน              |

การเชื่อม **Wallet จริง** ผ่าน MetaMask หรือ injected EIP-1193/EIP-6963 wallet มีไว้เลือกบัญชีเพื่อกรองรายการสาธิตที่มีอยู่เท่านั้น ไม่เปลี่ยนสิทธิ์ของบัญชีสาธิต ไม่เปลี่ยนเครือข่าย และไม่ขอลายเซ็นหรือส่งธุรกรรม หน้า “ใบรับรองของฉัน” แยกตัวเลือกบัญชีสาธิตและ Wallet จริงออกจากกัน รองรับการเปลี่ยนบัญชี เครือข่าย และการตัดการเชื่อมต่อจากกระเป๋า ปุ่มตัดการเชื่อมต่อเป็นการล้างสถานะในแอป ไม่ใช่เพิกถอนสิทธิ์เว็บไซต์ในกระเป๋า

## ข้อมูลและข้อจำกัด

- ข้อมูลอยู่ใน localStorage key `skilltrust.demo.v1` แยกตาม origin และเบราว์เซอร์ รีเฟรชแล้วข้อมูลยังอยู่ แต่ผู้ใช้แก้ไขหรือลบได้ จึงไม่ใช่หลักฐานหรือการตรวจสิทธิ์ที่เชื่อถือได้สำหรับใช้งานจริง
- QR เก็บเฉพาะลิงก์ตรวจสอบรหัส **ข้อมูลที่สร้างใหม่จะไม่ตามไปยังเครื่องหรือเบราว์เซอร์อื่น** จนกว่าจะเชื่อม Backend กลาง ใบตัวอย่างเริ่มต้นจะมีอยู่ในแต่ละเบราว์เซอร์
- สแกนด้วยมือถือ: เปิดเว็บด้วย Network URL ของเครื่องบน Wi-Fi เดียวกันก่อนสร้าง/แสดง QR ลิงก์ `localhost` บนมือถือจะชี้ไปยังมือถือเอง
- การคำนวณ Hash ต้องใช้ secure context (`HTTPS` หรือ `localhost`) การเปิด Network URL แบบ HTTP บนมือถืออาจค้นหาและดูสถานะได้ แต่ตรวจ Hash ไม่ได้ ควรใช้ HTTPS เมื่อต้องสาธิตการตรวจไฟล์ข้ามอุปกรณ์
- ระบบอ่าน PDF เพื่อตรวจ signature `%PDF-` และคำนวณ Hash เท่านั้น ไม่แสดงเนื้อหา ไม่ส่งไฟล์ออกเครือข่าย และไม่เก็บไฟล์หรือชื่อไฟล์ใน localStorage การตรวจ Hash ไม่ใช่การตรวจว่าเนื้อหา PDF ปลอดภัยหรือเป็นคุณวุฒิที่ถูกต้องตามกฎหมาย
- Hash ตรงกันยืนยันเฉพาะว่า bytes ตรงกับหลักฐานที่บันทึก หากใบรับรองถูกเพิกถอน ระบบยังแสดงว่าไม่มีผลใช้งาน
- วันที่ออกใช้วันตามเครื่องผู้ใช้ในโหมดสาธิต วันที่แสดงใช้ปฏิทินไทยและเขตเวลา Asia/Bangkok เมื่อเชื่อมจริงต้องยึดข้อมูลและข้อจำกัดเวลาของ Contract
- ไม่มีชื่อ อีเมล หรือข้อมูลส่วนบุคคลในแบบฟอร์ม รับข้อมูลผู้รับผ่าน Wallet เท่านั้น Wallet เป็นข้อมูลสาธารณะและสามารถเชื่อมโยงบุคคลได้ ควรประเมินการเปิดเผยข้อมูลตามระบบจริง
- เมื่อ localStorage อ่านไม่ได้ เต็ม หรือข้อมูลเสียหาย ระบบแจ้งข้อผิดพลาดและไม่รายงานว่าบันทึกสำเร็จ ข้อมูลเสียหายจะไม่ถูกเขียนทับอัตโนมัติ ต้องยืนยันรีเซ็ตเอง
- รองรับการซิงก์การเปลี่ยนแปลงข้ามแท็บผ่าน `storage` event แต่ไม่ได้ออกแบบสำหรับการเขียนพร้อมกันจากหลายแท็บ/ผู้ใช้ ใช้ Smart Contract เป็นแหล่งข้อมูลจริงเมื่อ Backend พร้อม
- ไม่มีระบบสร้างใบรับรอง PDF, upload/storage server หรือจัดเก็บข้อมูลส่วนบุคคลฝั่งเซิร์ฟเวอร์ ไฟล์ PDF ใน `public/` เป็น test fixture ที่เตรียมไว้เท่านั้น

## เตรียมเชื่อม Backend จริง

UI เรียกผ่าน `CertificateService` ใน `src/domain.ts` ได้แก่ `listCourses`, `listCertificates`, `findCertificate`, `permissions`, `createCourse`, `issueCertificate` และ `revokeCertificate` ส่วนโหมดสาธิตอยู่ใน `src/mock-service.ts` พร้อม versioned schema และ validation ด้วย Zod

ต้องได้รับข้อมูลต่อไปนี้ก่อนเชื่อมจริง:

1. Contract Address และ Chain ID ที่ deploy แล้ว พร้อม RPC และ block explorer
2. ABI หรือ Solidity source ที่ตรงกับ deployment รวมฟังก์ชัน events errors รูปแบบรหัส และรูปแบบข้อมูลใบรับรอง
3. วิธีตรวจสิทธิ์ผู้ดูแลและผู้ออก วิธีค้นหาใบรับรองตาม Wallet และจุดเริ่ม scan events หาก Contract ต้องอ่านผ่าน events
4. รูปแบบ Hash ที่ Contract รับ รวม algorithm, encoding และวิธีอ้างอิงข้อมูลผู้รับ ระบบปัจจุบันใช้ SHA-256 ของ bytes ทั้งไฟล์ เป็น hex 64 ตัวอักษรไม่มี `0x` ต้องแปลงใน adapter ตาม ABI จริง

ขั้นตอนเชื่อม:

- คัดลอก `.env.example` เป็น `.env.local` แล้วกำหนดค่าจริง ห้ามใส่ private key หรือ secret ลงตัวแปร `VITE_*` เพราะค่าจะถูกฝังใน browser bundle
- ใช้ `parseBackendConfig` และ `createBackendReader` ใน `src/connection.ts` สำหรับเตรียม public client จากนั้นเขียน adapter ที่ implements `CertificateService` ตาม ABI จริง โดยยังไม่ควรสมมติชื่อฟังก์ชัน Contract
- การเขียนจริงต้องใช้บัญชีจาก Wallet ที่เชื่อมต่อ ตรวจ Chain ID ตรวจสิทธิ์บน Contract จำลองการเรียกก่อนส่ง รอ receipt ตรวจ transaction revert และ refresh ข้อมูลหลังยืนยัน
- เปลี่ยน service และแหล่งบัญชีจัดการใน `App` ให้เป็น adapter กับ Wallet จริง ถอดบัญชีสาธิตและ localStorage ออกจากการตรวจสิทธิ์จริง ป้ายโหมดสาธิตต้องเปลี่ยนเฉพาะเมื่อเชื่อมจริงครบแล้ว
- ทดสอบ Contract integration สำหรับรหัสซ้ำ สิทธิ์ การออก/เพิกถอน การค้นหาตาม Wallet Hash และ QR ข้ามอุปกรณ์ รวมกรณีผิดเครือข่าย RPC ล่ม ผู้ใช้ปฏิเสธธุรกรรม และธุรกรรมไม่สำเร็จ

ไม่มี ABI ปลอมและไม่มีการเปิดใช้งานจริงอัตโนมัติจาก `.env` ในรุ่นนี้

## การทดสอบ

Vitest ครอบคลุม domain/service, การอ่านและบันทึก localStorage, Hash ของ PDF fixture, input validation, สิทธิ์และรหัสซ้ำ, Wallet ที่ไม่มี/ถูกปฏิเสธ รวมถึง UI integration ด้วย Testing Library ตั้งแต่สร้างหลักสูตรจนเพิกถอนโดยคงประวัติ และการเปิด deep link จาก QR

ทดสอบ browser wallet ผ่าน provider จำลองเพื่อไม่รบกวนกระเป๋าจริง การเชื่อม Wallet extension และ Smart Contract บนเครือข่ายจริงต้องตรวจเพิ่มเติมเมื่อมี Backend
